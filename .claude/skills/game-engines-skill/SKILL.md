- **เติมแพทเทิร์น (`pattern`, quiz ปกติใน `#cat-grid`)**: โจทย์แบบรูป emoji เลือกตัวต่อไป — คลัง 30 ข้อมี `q.tier:1-3` (ง่าย ABAB / กลาง ABCABC+AABB / ยาก จำนวนเพิ่ม-ลด, ไล่เฉด, ไล่ลำดับเลข) + `cat.poolPick:10` — `pickQuizQuestions()` ใน `js/app.js` สุ่มโจทย์ต่อรอบเกลี่ยตาม tier เรียงง่าย→ยากเสมอ (10 ข้อ = 4/3/3, "ทำอีกครั้ง" สุ่มชุดใหม่, หมวด quiz ที่ไม่มี `poolPick` ใช้โจทย์ครบทุกข้อเหมือนเดิม, การ์ดหน้า home โชว์จำนวนข้อจาก `poolPick`) — `q.pattern` (array emoji ต่อการ์ด) render พิเศษใน `renderQuestion()`: แถวการ์ด `.pat-tile` + ช่อง `?` เส้นประเต้น (`.pat-missing`), ตัวเลือกปุ่ม emoji ใหญ่ (`.choice-emoji`, การ์ดหลายตัวเช่น '🍎🍎🍎' ย่อฟอนต์ด้วย `graphemeLen()` — นับ grapheme ผ่าน `Intl.Segmenter` เพราะ emoji keycap อย่าง 1️⃣ ใช้ `.length` ตรงๆ ไม่ได้), ข้อผิดใน review-wrap สรุปโจทย์เป็น `q.pattern.join(' ')+' ❓'` — ถ้าเพิ่มหมวด quiz ใหม่ที่อยากสุ่มโจทย์ต่อรอบ ใช้ `poolPick` (+`tier`) ซ้ำได้เลย
- **หน้าเลือกหมวดมี "โหมดเกม" หลายแบบ** แต่ละแบบมี `<section>`/view-switching logic ของตัวเอง: (1) quiz ปรนัย (`quiz-view`, ไม่มี `type`, มี `questions` array) (2) AR กล้อง (`ar-view`, `type:'ar'`, มี `levels`) (3) **เกมฝึกทักษะ** (`memory-view`/`shadow-view`/`mix-view`/`music-view`, `type:'skill'`) (4) เกมฟังคำ (`listen-view`, `type:'listen'`) (5) **เกมฝึกเขียน** (`dots-view`, `type:'write'`) — หน้าเลือกหมวดมี 5 section: "คำถาม-คำตอบ" (`#cat-grid`), "การโต้ตอบ (AR)" (`#cat-grid-interactive`), "เกมฝึกทักษะ" (`#cat-grid-skill`), "เกมฟังคำศัพท์" (`#cat-grid-listen`), "เกมฝึกเขียน" (`#cat-grid-write`, เพิ่มเมื่อ 2026-07-17) `renderHome()` ใช้ `cat.type` ตัดสินว่า grid ไหน/`startQuiz`/`startARGame`/`startMemoryGame`/`startListenGame`/`startDotsGame` ตัวไหน (`type:'skill'` แยกย่อยด้วย `cat.mode`: shadow/mix/music → `startShadowGame`/`startMixGame`/`startMusicGame`) — **ถ้าเพิ่ม view ใหม่ ต้องไล่หา `arView.hidden`/`quizView.hidden`/`memoryView.hidden`/`shadowView.hidden`/`mixView.hidden`/`musicView.hidden`/`listenView.hidden`/`dotsView.hidden` ทุกจุดที่มีการซ่อน view ทั้งหมด (home-btn, switch-child-btn, ทุก `start*Game` ที่ต้องซ่อน view อื่นทั้งหมดตอนเข้าเกม) แล้วเพิ่ม view ใหม่เข้าไปด้วยเสมอ ไม่งั้นจะมี 2 view ซ้อนกันได้**
  - **`skill-memory` ("จับคู่โดมิโน")**: เกมความจำกดพลิกการ์ด (ไม่ใช้กล้อง เล่นได้ทั้งมือถือ/แท็บเล็ต/เดสก์ท็อป ไม่มี `desktopOnly`) แบ่งจอ 2 ฝั่ง `#memory-col-dots` (การ์ดจุด, อยู่ซ้าย) / `#memory-col-numbers` (การ์ดตัวเลข, อยู่ขวา) ค่าตัวเลข/จุดสูงสุดคือ **12** มี **3 ด่าน** แต่ละด่านสุ่มค่าไม่ซ้ำจำนวน `MEMORY_LEVEL_PAIRS[level-1]` คู่ (ใน `js/data.js`, ด่าน 1-3 = 4,8,12 คู่ตามลำดับ) shuffle ตำแหน่งฝั่งเลขกับฝั่งจุด**แยกกันเป็นอิสระ**ไม่ให้ตำแหน่งบอกใบ้คู่กัน
  - ดีไซน์การ์ด `.memory-card` ขนาด 92×120px (tablet) / 108×140px (`@media min-width:1025px`) ลายหลังการ์ดใช้ `repeating-linear-gradient` ทแยงทับสีพื้น (การ์ดตัวเลขใช้ `var(--cat-color)` สีของหมวดเอง, การ์ดจุดใช้ `var(--thai)` สีฟ้าประจำแอป) พร้อมไอคอนกลางในวงกลมขาวโปร่ง — ห้ามเปลี่ยนกลับไปใช้ flat gradient เดิมโดยไม่ถาม
  - **การ์ดจุดออกแบบเป็นโดมิโนจริง** (`dominoCardHtml()` ใน `js/app.js`): แบ่งครึ่งบน-ล่าง (`.domino-half` × 2 คั่นด้วย `.domino-divider`) แต่ละครึ่งวางจุดได้สูงสุด 6 จุดตามแพทเทิร์นโดมิโนจริง (`DOMINO_PIPS` lookup 0-6 จุด, ตำแหน่งอิงกริด 3×3 ผ่านคลาส `.pip-tl/.pip-tr/.pip-ml/.pip-c/.pip-mr/.pip-bl/.pip-br`) ค่า N ถูกแบ่งเป็น `top=Math.ceil(N/2)`, `bottom=N-top` เสมอ (การันตีทั้งคู่ไม่เกิน 6 เพราะ N สูงสุด 12) — ถ้าจะขยายค่าสูงสุดเกิน 12 ในอนาคตต้องคิดวิธีแบ่งครึ่งใหม่เพราะเกิน 6/6 จะ overflow ครึ่งการ์ด
  - กลไก flip: คลิกการ์ดคว่ำ 1 ใบต่อฝั่ง (`memoryGame.openNumber`/`openDot`) ถ้าเปิดครบ 2 ฝั่งจะเทียบค่าทันที ตรงกัน→ค้างไว้ถาวร (`matched`), ไม่ตรง→ค้าง `mismatch` ไว้บนจอ**ไม่มี delay/timer คว่ำอัตโนมัติ** (`memoryGame.locked=true`) จนกว่าผู้เล่นจะคลิกการ์ดใบใหม่ใบใดก็ได้ ถึงจะคว่ำคู่เก่ากลับก่อน (`resetMismatch()`) แล้วเปิดใบใหม่ที่เพิ่งคลิกทันที — ออกแบบใหม่แทนของเดิมที่ใช้ `setTimeout` ตายตัว (เคยขยับ 800ms→1500ms→3000ms) เพราะเด็กแต่ละคนใช้เวลานับจุดไม่เท่ากัน ให้เวลาเท่าที่ต้องการจริงๆ แทน — CSS ใช้ 3D flip จริง (`perspective`/`transform-style:preserve-3d`/`backface-visibility:hidden`)
  - stars/progress ใช้เกณฑ์ mistakes เดียวกับเกม AR (`0→3, ≤4→2, else→1`) เพื่อความสม่ำเสมอทั้งแอป ไม่มี per-question review (`review-wrap` ซ่อนเสมอเหมือน AR)
  - **`skill-shadow` ("ทายเงา 1")**: เกมโจทย์+ตัวเลือกใน section เกมฝึกทักษะ (`type:'skill'`, `mode:'shadow'`, 15 ด่าน, เล่นได้ทุกอุปกรณ์) แต่**ใช้ view แยกของตัวเอง `#shadow-view`** ไม่ใช้ `memory-view` — `renderHome()` dispatch พิเศษด้วย `cat.mode==='shadow'` → `startShadowGame()` ใน `js/app.js`. โจทย์คือเงาสีดำของ emoji (CSS `filter:brightness(0)` บน `#shadow-prompt`) เมื่อตอบแล้วจะเฉลยสีจริงด้วยคลาส `.revealed` — **transition filter ต้องอยู่บน `.revealed` เท่านั้น ห้ามย้ายไป base rule** ไม่งั้นตอนขึ้นด่านใหม่เงาจะแว้บสีจริงให้เห็นก่อนค่อยๆ ดำ (เคยเป็นบั๊กมาแล้ว) ตัวเลือกเป็น emoji สีปกติ+ชื่อไทยกำกับ: ด่าน 1-5 = 3 ตัวเลือก, 6-10 = 4, 11-15 = 5 — คลังโจทย์ `SHADOW_ITEMS` ใน `js/data.js` แบ่ง 3 กลุ่ม (animals 18/fruits 12/objects 15 ชิ้น) แต่ละชิ้นมี **shape tag (`s`)** ตัวหลอกเลือกจาก tag เดียวกับคำตอบก่อน (เงาคล้ายกัน ท้าทายขึ้น) ถ้าไม่พอค่อยเติมสุ่มจากกลุ่มเดียวกัน และคำตอบไม่ซ้ำภายใน 1 รอบเล่นผ่าน `pickNoRepeatIdx` (used Set แยกต่อกลุ่ม) **ตอบผิด = นับ mistake, ไฮไลต์เฉลยตัวเลือกที่ถูก + เปิดสีเงา แล้วข้ามไปด่านถัดไปเลย ไม่ให้เลือกซ้ำ** (ตอบถูกค้าง 1.2s / ตอบผิดค้าง 1.6s ให้ดูเฉลย), ดาวใช้เกณฑ์ mistakes เดิม (`0→3, ≤4→2, else→1`) — เปลี่ยนชื่อจาก "ทายเงา" เป็น "ทายเงา 1" เมื่อ 2026-07-12 (id `skill-shadow` คงเดิม ห้ามเปลี่ยนเพราะ progress/สติกเกอร์ผูกกับ id)
  - **`skill-shadow2` ("ทายเงา 2", 👥, `overlap:2`) / `skill-shadow3` ("ทายเงา 3", 🎭, `overlap:3`)**: ภาคต่อทายเงา ใช้ `#shadow-view` + `startShadowGame`/`pickShadowChoice` เดิมทั้งหมด — `renderShadowLevel()` เช็ค `g.overlap>1` แล้วแยกไป `renderShadowOverlapLevel()`: โจทย์เป็นเงา emoji 2-3 ชิ้นซ้อนเหลื่อมกัน (span `.sp-i` + margin ติดลบ ~40% ใน class `.ov2`/`.ov3` บน `#shadow-prompt` — filter brightness(0) อยู่ที่ parent จึงดำรวมเป็นก้อนเดียว, class ov2/ov3 ตั้งใน `startShadowGame` ตอนเข้าเกม) ตัวเลือกเป็นชุด object (`{e:emoji ต่อกัน, n:'ชื่อ + ชื่อ', items:[...]}` — `pickShadowChoice` เดิมเทียบ `item.e===answer.e` ใช้ได้เลยเพราะ e เป็น string ต่อกัน) สุ่มชุดคำตอบจาก `shadowFlatPool()` (รวม 3 กลุ่ม 45 ชิ้น) บังคับ shape tag `s` ไม่ซ้ำในชุดให้เงาซ้อนยังแยกรูปทรงออก กันโจทย์ซ้ำในรอบด้วย `usedCombos` Set (`shadowComboKey`), ตัวหลอกแทนของจริง (di%k)+1 ชิ้นโดย**สุ่มตำแหน่ง**ที่ถูกแทน (ได้คละ ชิ้นแรกจริง-หลังหลอก / หลังจริง-แรกหลอก / หลอกหมด — user สั่งให้คละ ห้ามแทนจากท้ายเสมอ) ตัวแทนเลือก shape เดียวกับชิ้นที่ถูกแทนก่อน, ตัวเลือก: shadow2 = 3/4/5 ตามด่านเหมือนภาคแรก แต่ shadow3 capped ที่ 4 (ชุดละ 3 ชิ้นการ์ดกว้าง เกิน 4 จะล้นจอ), ล็อกตามลำดับผ่าน `CAT_REQUIRES`: shadow→shadow2→shadow3, icon `assets/icons/shadow-2/3.svg`
